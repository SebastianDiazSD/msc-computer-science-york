## What is Data Wrangling?
Data wrangling (also called **data munging**) is the process of manipulating and reshaping data so it answers a specific information requirement. Cleaning data (Week 4) removes quality issues; wrangling **restructures** the data into the shape the analysis needs.

The data preparation process is **not linear** — visualisation often reveals issues that require going back to clean or reshape before analysis can continue.

## 1. Hierarchical Indexing (MultiIndex) — Section 8.1

### What is it?
Hierarchical indexing allows a DataFrame or Series to have **multiple levels of row or column labels**. This enables compact representation of higher-dimensional data in a 2D structure.

Think of it as parent → child grouping: e.g., College → Subject, or Year → Quarter → Month.

```python
import pandas as pd
import numpy as np

# Create a Series with a 2-level index
data = pd.Series(
    [1.5, 2.3, 3.1, 4.7, 5.0, 6.2],
    index=[
        ['Whitby', 'Whitby', 'Whitby', 'Bridlington', 'Bridlington', 'Scarborough'],
        ['Art',    'Eng',    'Psych',  'Maths',       'Chem',        'Eng']
    ]
)
print(data)
# Access all entries for Whitby:
print(data['Whitby'])
# Access a specific cell:
print(data['Whitby', 'Art'])
```

### Unstacking and Stacking
`unstack()` converts the inner index level to columns — turning a stacked (long) format into a wide table.
`stack()` is the inverse — converts column headers back into row index levels.

```python
df = data.unstack()    # inner index → columns
print(df)

df_stacked = df.stack()  # columns → inner index
print(df_stacked)
```

### Creating a MultiIndex DataFrame directly
```python
arrays = [
    ['Year 1', 'Year 1', 'Year 2', 'Year 2'],
    ['M', 'F', 'M', 'F']
]
index = pd.MultiIndex.from_arrays(arrays, names=['Year', 'Gender'])
df = pd.DataFrame(np.random.randint(1, 20, (4, 3)),
                  index=index,
                  columns=['Art', 'Engineering', 'Psychology'])
print(df)

# Select a top-level group
print(df.loc['Year 1'])

# Select a specific cell
print(df.loc[('Year 1', 'M'), 'Engineering'])
```

### Key methods

| Method | Purpose |
|---|---|
| `df.unstack()` | Inner row index → columns |
| `df.stack()` | Column labels → inner row index |
| `df.swaplevel()` | Swap levels in a MultiIndex |
| `df.sort_index(level=0)` | Sort by a specific index level |
| `df.xs('label', level='name')` | Cross-section: select across one level |

## 2. Merging Datasets — Section 8.2

### When to merge
Data related to the same subject is often stored in separate files or generated by separate systems. Merging combines them based on a common key — like a SQL JOIN.

### `pd.merge()` — the core function

```python
df1 = pd.DataFrame({'customer_id': [1, 2, 3], 'name': ['Alice', 'Bob', 'Carol']})
df2 = pd.DataFrame({'customer_id': [1, 2, 4], 'purchase': [50, 30, 20]})

# Inner join — only matching keys
merged = pd.merge(df1, df2, on='customer_id')
print(merged)

# Left join — keep all of df1, NaN where no match in df2
left = pd.merge(df1, df2, on='customer_id', how='left')

# Outer join — keep everything, NaN for missing
outer = pd.merge(df1, df2, on='customer_id', how='outer')
```

### Join types

| `how=` | Behaviour |
|---|---|
| `'inner'` (default) | Only rows where key exists in **both** DataFrames |
| `'left'` | All rows from **left** DataFrame; NaN for missing right |
| `'right'` | All rows from **right** DataFrame; NaN for missing left |
| `'outer'` | All rows from **both**; NaN wherever no match |

### Different key column names
```python
pd.merge(df1, df2, left_on='id', right_on='customer_id')
```

### Merging on index
```python
pd.merge(df1, df2, left_index=True, right_index=True)
# Or equivalently:
df1.join(df2)   # .join() merges on index by default
```

### `pd.concat()` — stacking DataFrames
Concatenates DataFrames along an axis (vertically or horizontally):
```python
result = pd.concat([df1, df2], axis=0, ignore_index=True)  # stack rows
result = pd.concat([df1, df2], axis=1)                     # stack columns
```

> ⚠️ `merge` joins on **key values**; `concat` simply **appends** rows or columns.

## 3. Reshaping and Pivoting — Section 8.3

### Why reshape?
A dataset that looks correct in one shape may hide patterns or make analysis awkward. Pivoting allows you to rotate the data — rows become columns and vice versa — to get a different perspective.

### `pivot()` — reshape from long to wide
```python
df = pd.DataFrame({
    'store':  ['L1', 'L1', 'L3', 'L3'],
    'month':  ['Jan', 'Feb', 'Jan', 'Feb'],
    'sales':  [340, 220, 459, 343]
})

pivoted = df.pivot(index='store', columns='month', values='sales')
print(pivoted)
# month  Feb  Jan
# store
# L1     220  340
# L3     343  459
```

### `pivot_table()` — like `pivot` but handles duplicates via aggregation
```python
pd.pivot_table(df, values='sales', index='store', columns='month', aggfunc='sum')
```

### `melt()` — wide to long (reverse of pivot)
```python
melted = pivoted.reset_index().melt(id_vars='store',
                                    var_name='month',
                                    value_name='sales')
```

### `groupby()` + `agg()` — split-apply-combine (covered more in Lesson 3)
```python
df.groupby('store')['sales'].sum()
df.groupby(['store', 'month'])['sales'].agg(['sum', 'mean'])
```

## Summary: Wrangling Methods Quick Reference

| Task | Method |
|---|---|
| Multi-level row/column labels | `pd.MultiIndex` |
| Wide → long | `stack()` or `melt()` |
| Long → wide | `unstack()` or `pivot()` |
| Merge on key column | `pd.merge(..., on='key')` |
| Stack rows/columns | `pd.concat([df1, df2])` |
| Pivot with aggregation | `pd.pivot_table()` |

---

## Key Takeaways
- **Hierarchical indexing** lets you represent multi-dimensional data in a 2D structure without data duplication.
- **Merging** is conceptually identical to SQL JOINs — understanding `inner/left/right/outer` is essential.
- **Pivot and melt** are inverses of each other; use them to switch between "wide" and "long" data layouts depending on what analysis or visualisation you are building.
- Data wrangling is **iterative**, not a one-shot step — visualisation often reveals that more reshaping is needed.
