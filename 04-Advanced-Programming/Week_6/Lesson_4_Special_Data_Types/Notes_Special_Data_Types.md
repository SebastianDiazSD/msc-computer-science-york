## Why Special Data Types Matter
Not all data is a plain number or string. Some data carries implicit structure — a date implies a sequence, a timezone implies a location, a categorical label implies membership in a set. Treating these as plain values silently breaks analysis. This lesson covers the two most important special cases: **time-series data** and **categorical data**.

---

## 1. Time-Series Data

### Why it is a problem
Different regions format dates differently. Without knowing the source's convention, a date string is ambiguous:

| Date string | UK interpretation | US interpretation |
|---|---|---|
| `2/5/1998` | 2 May 1998 | 5 February 1998 |
| `9/11/2001` | 9 November 2001 | 11 September 2001 |
| `5/1/2003` | 5 January 2003 | 1 May 2003 |

Getting this wrong does not produce an error — it silently corrupts every date-dependent calculation.

Additional issues:
- **Timezones**: Timestamps generated by computers are local to the machine's timezone. Merging data from servers in different regions requires calibration to a single reference (typically UTC).
- **Irregular intervals**: Business data (trading days only), sensor data (variable frequency), and server logs all produce time series that are not uniformly spaced.

---

### Python `datetime` Types

```python
from datetime import datetime, date, timedelta

# Create a specific datetime
dt = datetime(2024, 3, 15, 14, 30, 0)   # year, month, day, hour, min, sec
print(dt)                                 # 2024-03-15 14:30:00
print(dt.year, dt.month, dt.day)

# Current datetime
now = datetime.now()

# Arithmetic with timedelta
one_week_later = dt + timedelta(days=7)
delta = datetime(2024, 12, 31) - datetime(2024, 1, 1)
print(delta.days)   # 365

# Parse string to datetime
dt_parsed = datetime.strptime('15/03/2024', '%d/%m/%Y')  # UK format
dt_us     = datetime.strptime('03/15/2024', '%m/%d/%Y')  # US format
```

### Common `strftime` / `strptime` codes

| Code | Meaning | Example |
|---|---|---|
| `%Y` | 4-digit year | 2024 |
| `%m` | Month (01–12) | 03 |
| `%d` | Day (01–31) | 15 |
| `%H` | Hour 24h (00–23) | 14 |
| `%M` | Minute (00–59) | 30 |
| `%S` | Second (00–59) | 00 |
| `%B` | Full month name | March |
| `%A` | Full weekday name | Friday |

### Pandas `DatetimeIndex` and `Timestamp`

Pandas has a first-class `Timestamp` type and `DatetimeIndex` which enable powerful time-series operations:

```python
import pandas as pd

# Parse dates when loading CSV
df = pd.read_csv('data.csv', parse_dates=['date_column'])
df = pd.read_csv('data.csv', parse_dates=True, index_col='date_column')

# Convert a column to datetime
df['date'] = pd.to_datetime(df['date_column'], format='%d/%m/%Y')
# Let pandas infer the format (slower but convenient):
df['date'] = pd.to_datetime(df['date_column'], infer_datetime_format=True)

# Handle UK vs US ambiguity explicitly:
df['date'] = pd.to_datetime(df['date_str'], dayfirst=True)   # UK: day/month
df['date'] = pd.to_datetime(df['date_str'], dayfirst=False)  # US: month/day
```

### Slicing time series
When a DatetimeIndex is set, you can slice with date strings:
```python
df = df.set_index('date')

df['2023']                          # entire year 2023
df['2023-03']                       # entire March 2023
df['2023-01-01':'2023-06-30']       # date range (inclusive both ends)
df.loc['2023-03-15']                # specific day
```

### Resampling — changing the time frequency
```python
# Aggregate daily data to monthly totals
monthly = df['sales'].resample('M').sum()

# Weekly mean
weekly_mean = df['sales'].resample('W').mean()

# Quarterly sum
quarterly = df['sales'].resample('Q').sum()
```

Common resample frequency aliases: `'D'` (day), `'W'` (week), `'M'` (month end), `'MS'` (month start), `'Q'` (quarter), `'Y'` (year).

### Timezone handling
```python
# Set timezone
df_utc = df.tz_localize('UTC')

# Convert to a different timezone
df_berlin = df_utc.tz_convert('Europe/Berlin')
df_london = df_utc.tz_convert('Europe/London')
```

### Extracting components
```python
df['year']    = df.index.year
df['month']   = df.index.month
df['day']     = df.index.day
df['weekday'] = df.index.day_name()   # 'Monday', 'Tuesday', etc.
df['quarter'] = df.index.quarter
```

## 2. Categorical Data

### What is categorical data?
Most data seen so far has been numerical. Categorical data uses **labels or descriptions** rather than numbers. There are three subtypes:

| Type | Description | Example |
|---|---|---|
| **Nominal** | Labels with no order, no value | Colours: blue, red, green |
| **Ordinal** | Labels with an implied order but no numeric value | Education: High School < College < Graduate |
| **Dichotomous** | Only two possible values | Male/Female, True/False, Pass/Fail |

### The coding trap
Categorical data is often stored as numbers (e.g., 0 = male, 1 = female). This is called **coding** and is done for storage efficiency. **But the numbers have no mathematical meaning** — there is no sense in which female (1) is "more than" male (0), or in which you should average the two. Operations like mean on coded categories are statistically meaningless.

Pandas `Categorical` dtype signals to the library and to other developers that a column should be treated as categorical, not numerical:

```python
df['education'] = pd.Categorical(
    df['education'],
    categories=['High School', 'College', 'Graduate'],
    ordered=True    # signals ordinal ordering
)

# Now comparison operators work correctly:
df[df['education'] > 'High School']
```

### Inconsistency problems
Categorical labels are a common source of cleaning issues:
- Spelling variations: `'Accounting'` vs `'accounting'` vs `'ACCOUNTING'`
- Overly specific categories that don't accommodate new data (see the bird/domestic animal example — where does "chicken" go?)
- Mixed encoding: some rows use the full label, others use a numeric code

```python
# Standardise case
df['job_title'] = df['job_title'].str.strip().str.title()

# View all unique values to spot inconsistencies
print(df['job_title'].value_counts())

# Map related labels to a consistent parent category
mapping = {'Software Engineer': 'Tech', 'IT Support Staff': 'Tech',
           'Chef Manager': 'Hospitality', 'Cook': 'Hospitality'}
df['sector'] = df['job_title'].map(mapping)
```

### Pandas `Categorical` — memory and performance
For large datasets with a small number of distinct values, using `Categorical` dtype significantly reduces memory:

```python
df['city'] = df['city'].astype('category')

print(df['city'].cat.categories)    # all unique categories
print(df['city'].cat.codes)         # integer codes assigned to each category

# For ordinal data, set an explicit order:
from pandas.api.types import CategoricalDtype
edu_type = CategoricalDtype(
    categories=['Middle school', 'High school', 'College', 'Graduate school'],
    ordered=True
)
df['education'] = df['education'].astype(edu_type)
```

## 3. Data Type Identification Checklist

Before analysing any new dataset, ask these questions:

| Question | Why it matters |
|---|---|
| Are any date columns stored as strings? | `pd.to_datetime()` must be applied before slicing or resampling |
| What timezone is the data in? | Merging data from different sources requires calibration |
| Are numeric columns actually categorical codes? | Prevent meaningless arithmetic on coded labels |
| Is a categorical column nominal or ordinal? | Ordinal requires explicit ordering before comparison |
| Are there inconsistent label spellings? | Must be standardised before `groupby()` will work correctly |

---

## Key Takeaways
- **Date ambiguity is silent** — always know whether your source uses UK (day/month) or US (month/day) format before parsing. Use `dayfirst=True` or explicit `format=` strings.
- **Resampling** lets you change temporal granularity — `'D'` to `'M'`, `'M'` to `'Q'` — with a single line.
- **Categorical dtype** tells Pandas (and you) that a column is a label, not a number, even when encoded numerically.
- **Ordinal categories** require explicit ordering via `CategoricalDtype(ordered=True)` for comparison operators to work correctly.
- Inconsistent category labels break `groupby()` silently — a row labelled `'Accounting'` and one labelled `'accounting'` will be counted as two separate groups.
